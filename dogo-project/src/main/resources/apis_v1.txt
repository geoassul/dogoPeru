🔐 1. AUTENTICACIÓN (/auth)
============================================================================

1.1 POST /auth/login
    Descripción: Iniciar sesión y obtener token JWT
    Headers: Content-Type: application/json
    Body (JSON):
    {
        "username": "admin",
        "password": "password"
    }

    {
        "success": true,
        "message": "Login exitoso",

💰 7. VENTAS (/api/ventas) - lectura y POST /completa ADMIN/USER, resto ADMIN
============================================================================

7.1 GET /api/ventas
    Descripción: Obtener todas las ventas
    Headers: Authorization: Bearer {token}
    Respuesta:
    {
        "success": true,
        "message": "Datos obtenidos correctamente",
        "data": [
            {
                "id": 1,
                "fechaVenta": "2025-09-05T14:30:00",
                "totalVenta": 90.00
            }
        ]
    }

7.2 GET /api/ventas/{id}
    Descripción: Obtener venta por ID
    Headers: Authorization: Bearer {token}
    URL: /api/ventas/1

7.3 POST /api/ventas/completa   (RECOMENDADO para registrar ventas - ADMIN/USER)
    Descripción: Registra la venta y sus detalles en una transacción. Valida y descuenta
                 stock (con bloqueo de filas), toma precio y costo de cada variante y calcula
                 el total. Los campos "total" y "precio_unitario" se ignoran si se envían.
    Headers: 
        Authorization: Bearer {token}
        Content-Type: application/json
    Body (JSON):
    {
        "fecha_venta": "2025-09-05T14:30:00",      (opcional, por defecto ahora)
        "detalles": [
            { "variante_producto_id": 1, "cantidad": 2 },
            { "variante_producto_id": 5, "cantidad": 1 }
        ]
    }
    Respuesta 201: la venta creada con sus detalles (VentaDTO)
    Errores: 400 variante inexistente o datos inválidos, 409 stock insuficiente

7.3b POST /api/ventas   (ADMIN)
    Descripción: Con "detalles" se comporta igual que /completa. Sin detalles crea solo la
                 cabecera (flujo antiguo: las líneas se agregan con /api/detalle-venta y no
                 descuentan stock).
    Body (JSON): { "fechaVenta": "...", "totalVenta": 90.00, "detalles": [{ "varianteId": 1, "cantidad": 2 }] }

7.4 PUT /api/ventas/{id}   (ADMIN)
    Descripción: Solo cambia la fecha (el total y el stock dependen de los detalles)
    Body (JSON): { "fechaVenta": "2025-09-05T14:30:00" }

7.5 DELETE /api/ventas/{id}
    Descripción: Eliminar venta y sus detalles (ADMIN ONLY). No repone stock.
    Headers: Authorization: Bearer {token}
    URL: /api/ventas/1

7.6 GET /api/ventas/fecha?fechaInicio={inicio}&fechaFin={fin}
    Descripción: Obtener ventas por rango de fechas
    Headers: Authorization: Bearer {token}
    URL: /api/ventas/fecha?fechaInicio=2025-09-01T00:00:00&fechaFin=2025-09-30T23:59:59

7.7 GET /api/ventas/recent
    Descripción: Obtener las 5 ventas más recientes
    Headers: Authorization: Bearer {token}
    Respuesta: Array de las últimas 5 ventas ordenadas por fecha

🔐 NOTAS DE AUTENTICACIÓN Y AUTORIZACIÓN
============================================================================

ROLES Y PERMISOS:
- ADMIN: Acceso completo a todos los endpoints (CRUD), usuarios y dashboard
- USER (vendedor): lectura de productos/variantes/imágenes/ventas y registro de ventas
  con POST /api/ventas/completa. No puede crear, editar ni borrar catálogo ni ventas.

HEADERS REQUERIDOS:
- Authorization: Bearer {token} (para endpoints protegidos)
- Content-Type: application/json (para POST/PUT)
- Content-Type: multipart/form-data (para upload de archivos)

CÓDIGOS DE RESPUESTA:
- 200: Éxito
- 201: Creado exitosamente
- 400: Error de validación o solicitud incorrecta
- 401: No autorizado (token inválido o faltante)
- 403: Prohibido (sin permisos suficientes)
- 404: Recurso no encontrado
- 409: Conflicto (stock insuficiente, registro duplicado o con registros relacionados)
- 500: Error interno del servidor

FORMATO DE RESPUESTA ESTÁNDAR:
{
    "success": boolean,
    "message": "string",
    "data": object|array|null
}

VALIDACIONES COMUNES:
- Campos obligatorios marcados con * en documentación
- Categorías y proveedores: nombre de 2 a 30 caracteres
- Productos: nombre de 2 a 100 caracteres
- Teléfonos: de 7 a 10 caracteres (números, espacios, +, -, paréntesis)
- IDs: Números positivos

📋 EJEMPLOS DE USO EN POSTMAN
============================================================================

COLECCIÓN RECOMENDADA:
1. Crear carpeta "DoGo Store API v1"
2. Subcarpetas por módulo (Auth, Categorías, etc.)
3. Variables de entorno:
   - baseUrl: http://localhost:8080
   - token: (se actualiza automáticamente en login)

SCRIPT PRE-REQUEST (para endpoints protegidos):
pm.request.headers.add({
    key: 'Authorization',
    value: 'Bearer ' + pm.environment.get('token')
});

SCRIPT POST-RESPONSE (para login):
if (pm.response.code === 200) {
    const response = pm.response.json();
    if (response.success && response.data.token) {
        pm.environment.set('token', response.data.token);
    }
}
